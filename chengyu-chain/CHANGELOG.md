# Changelog

## [0.2.0] - 2026-10-29

- T1/Q1 统一加载机载标准 aimdk_msgs，独立入口和跨板命令拒绝私有旧消息包混用。
- 按 Q1、T1 双足、T1 四足核对动作与资源；适配 T1 形态过滤、命名 Mimic NONE 类型及双足稳定返回模式。

### Features

- 包内声明 `primebuddy.version: 1`、独占运行模式及配置、启动、状态和恢复 CLI，配套 Buddy 1.2.0 的完整安装包。
- `play --hosted` 由 Buddy 管理原厂 only_voice 生命周期，游戏管理整局收音与答题，结束后交还宿主。

### Fixes

- 仅接受有效答题窗口内原厂 LISTENING 状态的新完整语句；唤醒应答、SPEAKING、IDLE 及跨状态半句不提交 ASR。
- 退出和错误路径先清理播放及子进程资源，再让 Buddy 接管；IDLE 本身不结束游戏，静默退出由游戏独立计时。
- Q1 动作资源查询补齐当前 SDK 要求的 form_state，提前拒绝不匹配的旧消息接口。
- 原厂模式服务采用稳定发现、只读握手、一次设置及读回确认；恢复 normal 的失败保留恢复记录。
- SDK 环境优先匹配目标固件当前接口目录，避免使用 housekeeper 的旧消息包。

### Upgrade notes

- 保留原配置和登录、运行数据，升级不自动打开身体动作；向导可通过 Buddy 调用，也可独立运行。
- Buddy 1.1.0 不具备当前完整的游戏交接保证，请使用 Buddy 1.2.0；独立使用仍不导入 Buddy Python 模块。

### Known issues

- T1 四足起身准备、开心动作及主动取消归位已通过本次实机接口和状态验证；表情请求与复位获得原厂确认，观感未作人工评价。后续难过动作被充电器接入保护拦截，双足和剩余动作未完成验收；没有写入永久动作启用或验收标记。
- 游戏退出后 Buddy 接管已有用户现场验收；“唤醒词＋答案”连说不保证接收，请等原厂应答结束再回答。T1 的新增动作路径仍须按形态单独验收。
- Q1 游戏内动作联动、异常取消及 T1 当前版本仍需现场验收；不自动从折叠或躺姿起身。
- 独立语音前端互斥只覆盖同一控制器，不能跨板同时启动多个管理实例。

## 0.1.0 — 2026-10-24

### Features

- 四项可配置 `speech` 播音词：答对鼓励、获胜赞美、升级邀请、失败安慰；答对报本局进度。
- 独立语音成语接龙、同音不分声调/前后鼻音、解释与提示、三级5/7/10次通关、三次明确接错判负。
- 多局连续独占；30秒答题、两次提醒和每局一次援助，120秒无有效回应退出。
- 对齐Buddy的安装向导、模型匹配的中文音色菜单；本地验证完整同音转写。
- CLI持久动作开关及单次覆盖，T1站立准备/难过协议及独立验收门禁。
- 独立模型配置、Buddy 安装默认值、私有结束播报缓存。
- T1/Q1 普通答对、明确接错分别播放开心、难过表情；通关与失败才触发已启用且已验收的身体动作。

### Fixes

- 最后一次有效回答达到通关目标后，不再因无须使用的机器人下一成语无效而阻断获胜。
- TTS 模型切换时推荐匹配的音色，避免 3.1 模型沿用 3.0 默认音色导致 HTTP 400。
- 配置后生成结束播报失败时说明配置已保存，并区分 TTS 合成与音频下载错误。
- 将千问 3.1 ASR 明确返回的 `ASR_RESPONSE_HAVE_NO_WORDS` 作为空识别处理，避免静音触发云接口错误提示；其他接口错误仍按失败处理。

### Compatibility

- Buddy 宿主须包含 `interaction: exclusive` 支持；独立运行不导入宿主包。

### Validation

- 316 项单元测试通过。Q1 上使用合成语音文件完成初级 5 次获胜、进入中级、退出交还 Buddy，以及静音不重复报错的验证。
- Q1 开心摆臂、开心表情和自然归位已完成一次现场验证；难过表情及复位有显示状态反馈，尚未取得人工观感确认。

### Known issues

- 实体动作默认关闭；Q1 失望身体动作资源及非站立转换尚未核实。动作中途取消、游戏内晋级身体联动、中高级通关和修复后的真人麦克风路径仍需现场验证。
- T1 双足、四足仍需分别完成当前版本验收；ROS 冷客户端首个请求偶发无回复问题尚未定位。
- 跨控制器不能同时运行多个独立前端管理实例。
