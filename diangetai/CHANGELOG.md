# Changelog

点歌台的版本更新记录。安装、命令和配置说明见 [README](README.md)。

## [0.4.0] - 2026-10-23

### Features

- **正式支持 Q1 型号**：在已有 T1 支持基础上，新增原厂型号识别、媒体播放和音乐联动适配；可在媒体服务所在板本地运行，也可跨板准备音频并播放。
- **独立 CLI**：提供 `configure`、`context`、`check-play`、`play`、`status` 和 `recover`。技能自行管理歌曲转码、原厂播放、运行锁及清理，不再依赖 PrimeBuddy 的 Python 业务接口；命令返回 JSON，可由其他宿主调用。
- **Q1 连续舞蹈**：在音乐实际开始后随机轮换原厂 A/B/C 预设，每段确认完成才开始下一段，避免相邻重复。音乐结束后确认默认姿态和稳定站立，再完成清理。
- **QQ 登录自动续期**：配置、搜索和取流复用原设备身份及完整登录凭据；登录过期时先续期，取流最多重试一次。仅首次登录、缺少刷新凭据或刷新授权失效时进入扫码流程。
- **播放状态与恢复**：提交播放前保存本次媒体记录，支持协作取消和 `status/recover`。只有确认本次终态才清除记录，结果通过 `resources_released` 单独报告资源是否已释放。

### Fixes

- **Q1 舞蹈无法连续执行**：兼容原厂查询返回全局任务状态的行为，结合提交后新鲜的自有 MC task ID 确认动作生命周期；不再仅凭查询响应中的 task ID 判断归属，也不把全局 SUCCESS 当作本次动作完成。
- **登录凭据轮换后丢失或被覆盖**：原子保存完整新凭据并更新当前客户端；配置、扫码和取流共用账号锁，避免并发刷新覆盖登录态。续期后的检查即使断网，也保留已轮换凭据。
- **异常时误导用户反复扫码**：网络错误、设备数量上限、频率限制和其他业务拒绝返回对应原因，不自动转为扫码；扫码完成后向服务器核实登录。
- **未确认停止却报告释放**：错误反馈、停止请求被接受或进程退出都不视为媒体已停止；保留未确认记录，新恢复进程不会重复发送已记录的停止请求。播放前先确认媒体状态订阅匹配，避免漏掉本次状态反馈。

### Compatibility

- 支持启元 T1/Q1，使用目标机器人已有的 ROS 2、`rclpy`、`aimdk_msgs` 和原厂媒体服务；需要 Python 3.10 或更新版本、GStreamer 解码环境及有效 QQ 音乐登录。
- 独立使用无需安装 PrimeBuddy。与框架集成时配套 **PrimeBuddy 1.1.0**；该框架声明点歌台兼容范围为 `>=0.4.0, <0.5.0`，推荐 `0.4.0`，后续以目标框架的 `release.json` 为准。
- 0.4.0 改用独立 CLI，不能沿用 0.3.0 的旧 Python 入口接入方式；新版 Buddy 的 CLI 适配也不能调用旧点歌台 0.3.0。
- Q1 联动要求稳定的 `BIPED_WALK_RUN(1002)`，以及实际可用的原厂预设动作和状态查询接口，不从被动或躺姿自动起身。独立点歌不切换 Agent 模式，播放前原厂会话须已唤醒。

### Upgrade notes

- 独立安装更新代码和 Python 依赖后，继续使用原配置、数据和运行目录。默认复用 `~/.primebuddy/data/diangetai`，也兼容已有的技能配置路径；该目录名称不代表必须安装框架。
- 保留数据目录中的 `device.json` 和 `credential.json`，配置与播放始终使用同一数据目录。不要删除设备身份来处理登录问题，也不要把同一身份复制给其他机器人。
- PrimeBuddy 托管安装退出语音会话后使用 `primebuddy update` 联合升级；从框架 1.0.0 首次升级时，在原安装板解压 PrimeBuddy 1.1.0 包并运行 `source ./scripts/install.sh`。外部源码目录须自行更新。
- 联动开关沿用保存配置，不因升级自动开启。存在未确认恢复记录时先检查 `status`；`recover` 只处理记录中的自有媒体，不自动重放身体动作或删除联动恢复记录。

### Known issues

- Q1 提前停止音乐仍不可靠：已观察到原厂停止接口返回成功，但音乐继续到自然结束。播放中再次唤醒也不保证取消歌曲。
- Q1 的 60 秒正式 CLI 播放、13 段连续舞蹈和自然结束归位已有实机记录；完整真人唤醒、点歌及两首歌免唤醒续听仍待宿主端到端验收，不能据此宣称整条语音链路已通过。
- 跨轮“再来一首”仍需宿主维护点歌上下文，本技能不提供跨轮记忆。
- 强杀进程无法执行清理；终态反馈已错过、动作归属不明或归位未确认时，可能需要结合现场和原厂状态处理。服务端也仍可撤销 QQ 授权，自动续期不保证永久免登录。

## [0.3.0] - 2026-10-14

### Features

- 发布面向 T1 的 QQ 音乐点歌技能，可按歌手或歌名选歌，设置 `0～600` 秒播放时限；`0` 表示整首，播放时长从实际开播计算。
- 提供扫码登录及播放设置向导，复用有效登录态；支持可选的动作、表情和灯光联动，保留未确认的恢复记录。
- 通过 `SKILL.md` 和包信息声明业务入口，由框架提供语音、任务安排及音频播放；提供独立版本 RPK，随包包含 README 和 MIT LICENSE。

### Compatibility

- 当时配套 **PrimeBuddy 1.0.0**，安装说明面向 T1 业务板 SoC 1 和原厂 ROS 2 环境；尚未提供 0.4.0 的独立业务 CLI 与 Q1 适配。
